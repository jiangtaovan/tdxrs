# 新协议逆向研究（2026-09）

## 结论

2026-07 起通达信服务端对 pytdx 系旧帧（`0c 02` 系）**按功能族断供行情数据**：
TCP 可连、目录/财务类接口（security_count / security_list / finance_info /
**get_xdxr_info 仍存活**）照常应答，但实时快照、K 线、分时、逐笔对旧帧一律
静默返回空。官方金融终端改用本目录逆向出的**新帧格式**（详见
`python/tdxrs/v2_client.py` 模块 docstring）：

- 无握手密钥、无加密：裸 TCP + 正确帧格式即返回数据；
- 登录帧（80B）为静态字节串，可跨连接原样重放；
- 响应帧头 16B：`b1 cb 74 00 | u16 方法回显 | 8B | u16 载荷长 | u16 载荷长回显`；
- K线记录 36B：`[u32 日期][u32 时间][f32 开][f32 高][f32 低][f32 收]
  [f32 成交额(元)][f32 成交量(股)][f32 流通股本(万股)]`，载荷尾部 120B 为
  GBK 名称。时间字段日线为 0，分钟/小时线为距午夜秒数（37500=10:25:00，
  K 线**结束**时刻）；
- 分时记录 18B（记录区自载荷 offset 37 起）：`[f32 价格][f32 均价][u32 量]
  [u32 保留][u16 距午夜分钟数]`（571=09:31）；
- 市场字节：1=沪 0=深（与老协议一致）。

验证：600519 日K 700 根与已知行情逐字段一致（2026-09-11 收 1275.16），
全周期（5min/15min/30min/1h/日/周/月/季/年，枚举与老协议同值）、翻页偏移、
分时解码均在线实测通过。

## 2026-09-13 能力探测结论（probe_*.py）

- **bars 请求 u32@40 为起始偏移**：start=700 的窗口与最新窗口无缝衔接
  （末 2023-10-27 ↔ 基线首 2023-10-30 相邻）；count 单次上限 **700**
  （u16 载荷长字段约束，count>700 仍只回 700 条）；
- **周期类别枚举与老协议完全一致**：0/1/2/3=5/15/30/60min、4=日、5=周、
  6=月、10=季、11=年，全部有数据；
- **分时载荷步长 18B** 由三次探测的载荷增量（+36B=+2 条）锁定；
- **旧协议默认服务器（三方机房）不服务 v2 帧**（超时/拒连），v2 仅实测
  `121.36.248.138` 可用；
- **get_xdxr_info 仍存活**且返回完整除权史（600519 共 45 条含 2026-06-26
  派 280.24/10股；300750 共 75 条）——**除权未被断供**，qfq/hfq 走
  「v2 原始K线 + 旧协议除权 + 本地调整」（`python/tdxrs/adjust.py`，
  移植自 Rust `src/protocol/adjuster.rs`，在线验证：跨除权日因子
  (1212.10−28.0242)/1212.10 逐位精确）；
- xdxr 记录中只有 **category==1** 是真实综合除权事件（带 fenhong/songzhuangu
  等数值），category 2/3/5/9/14 全是空字段标记行，复权时跳过（与 Rust 一致）；
- **周/月/季/年线的成交量单位是「手」**（周线 ×100 恰等于日线股数加总），
  日线与分钟线是「股」——跨周期聚合量能时注意。

## 2026-09-14 榜单报价批逆向（抓包 captures/20260914_160646/）

Mac 版金融终端经 `record_proxy.py` 录制 + 方法号普查（响应帧头 `0c <方法号>`
在 magic 后偏移 +5）发现官方客户端的多票页面批帧，已实现为
`v2_client.get_rank_page / parse_rank_records / RankQuote`：

- **榜单轮询帧（55B，与 _SNAPSHOT 同骨架）**：@25=u16 榜单 id、@27=u16
  记录偏移、@31=页大小(32)。list_id 选择服务端榜单（14=全市场榜含北交所，
  0=北证、5=科创权重…均为涨跌排序）；offset 步进=页大小即翻全列表；
  **新连接无需上下文帧**，单连接可连续翻页（实测 175 页 / 9-11s 全市场）。
- **响应为裸批载荷**（无独立帧头）：`[24B 前缀][u32 记录数@24][N×196B 记录@28]`
  （页尾记录截短 2B）。196B 记录：`[6B ASCII 代码][16B 零][GBK 名称@22(32B)]
  [零@54][f32 昨收@66][f32 开@70][f32 高@74][f32 低@78][f32 现价@82]
  [u32 量(手)@86][4B][f32 额(元)@94]`；字段与单票快照(方法5)逐位一致，
  已用收盘后行情逐字段锚定验证。
- **方法 4 = 任意代码清单批（官方指数条同款帧）**：请求 `00 04 00 2b 12 01
  a8 00 a8 00 2b 12 93 00 00 80 + 16B 零 + u16 数量@32 + N×24B 槽位
  [u16 市场(0深1沪2北)][6B ASCII 代码][16B 零]`，@6/@8 u16 = 帧长-12；
  应答 88B/记录（仅 昨收@66/开@70/现@74/额@94± + 名称），无高低量。
  **一连接只应答一次**，二次请求超时——换清单须重连。
- 其他观测：方法 12=Stock_ZJLX 资金流、30/31/34=880005 涨跌家数族、
  23=板块行情批(~300 条)、27=会话 token；各方法响应头首字节恒为 `0c`。
- 事件背景：批帧发现前，盘中 5 分钟同步因停牌退化快照（`TdxV2NoQuote`）
  + 逐票串行（5558×48ms≈4.8 分钟）曾全灭；榜单批使全市场一轮 ~10 秒。

## 排障记录（后人少走弯路）

1. Mac 版「通讯设置」主站下拉为固定列表，**无法填自定义 IP**；
2. Mac 版「使用 HTTP 代理」对行情族 socket **无效**（重启进程验证）；
3. 帧边界要靠 TCP 流重组+前缀定位，直接取单包 payload 会混入相邻帧字节；
4. 服务端对格式正确但字段被写坏的帧**静默返回空回声**，不报错——
   偏移动一个字节就是"看起来连上了但没数据"；
5. 分时记录区起点（offset 37）不在 4 字节整数边界上，按 4 对齐扫描会漏掉
   绝大多数价格 float——先用载荷增量（两次探测之差 = N×记录长）锁步长；
6. 服务端「当日」时间可能比本机快（休市日仍返回下一交易日实时数据），
   分时/盘中 K 与本机日期对不上时先怀疑时钟差，不是解析错。
